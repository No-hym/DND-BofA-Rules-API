# Архитектура

## Версии стека

Зафиксированные стабильные версии (2026-11-26): Go 1.27.4, PostgreSQL 18, Chi 5.5.0, pgx 5.11.0, Goose 3.30.2, JSON Schema validator 6.0.3, sqlc 1.31.1, oapi-codegen 2.9.0/runtime 1.9.1, Testcontainers Go 0.45.0, golangci-lint 2.15.0. Go-модули/инструменты зафиксированы в `go.mod`, CI и Dockerfile.

## Слои

- `cmd/rules-api`: запускает HTTP сервер, структурированное логирование `slog`, таймауты и graceful shutdown.
- `internal/api`: Chi маршруты, валидация query-параметров, read-only REST поверх PostgreSQL.
- `cmd/rules`: валидатор, импорт/обновление, статистика, переключение книг и переводчик.
- `internal/content`: каноническая JSON-модель, проверка обязательных полей и стабильный fingerprint.
- `db/migrations`: Goose миграции; `db/queries` и `sqlc.yaml` фиксируют query contracts. Для SQL-запросов используется pgx, API читает через pgxpool.
- `data/catalog`: Git-версионируемый исходный каталог. `data/schema/entity.schema.json` — JSON Schema.

Приложение не вызывает внешние сервисы на пути API-запроса. Синхронизация Open5e и LLM-перевод выполняются отдельными явными командами импорта.

## Идентификаторы и дубликаты

ID включают источник/редакцию/категорию/slug; для вручную сопровождаемого SRD 5.2.1 используются IDs источника `srd:*`. Импорт проверяет дубли ID в снимке и выполняет транзакционный upsert по стабильному ID и ключу источника. Переводы связываются с неизменяемым ID, поэтому смена языка не меняет ссылку. Повторные записи одного source ID пропускаются при Open5e ETL.

`fingerprint` хранит SHA-256 от игрового mechanics JSON, чтобы выявлять изменения механик. Автоматическое слияние одноимённых сущностей из разных книг намеренно не выполняется: совпадение названия не доказывает идентичность механики. Точные/семантические дубликаты разных источников требуют отдельного аудита и не удаляются автоматически.

## PostgreSQL

Сущности и переводы нормализованы в `entities` и `entity_translations`; данные механик — JSONB. JSON Schema задаёт общие машиночитаемые ключи `requirements`, `limitations`, `choices`, `relations` и `compatibility`; категорийные данные могут добавлять свои свойства. `books.enabled` служит простым тумблером публикации книги. Индексы включают GIN JSONB, `pg_trgm` и полнотекстовый поиск `simple` для английских и русских строк. Список и поиск используют языковой fallback на EN для сущностей без RU, а ответ возвращает фактический `language` и статус перевода.

## Расширение

Категория — строковый идентификатор, поэтому возможны `class`, `subclass`, `species`, `background`, `feat`, `spell`, `feature`, `monster`, `equipment`, `condition`, `rule`, `level` и наборы Homebrew без смены схемы БД. Для каждого нового семейства следует добавить адаптер нормализации в канонический JSON и категорийную JSON Schema. Доступ к данным остаётся контрактно-ориентированным и без зависимости от внешнего поставщика в рантайме.
