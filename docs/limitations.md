Русские имена есть у **19.05%** записей (64/336); полный name+description текст переведён у **4.17%** (14/336). 50 имён монстров — только первый машинный черновик: их действия, черты и характеристики в `mechanics` остаются по-английски. Все 14 состояний помечены `machine` и требуют редакторской проверки. Все числа относятся к проверенному JSON-каталогу, а не к полному объёму правил D&D.

## Реализовано в этом срезе

- PostgreSQL schema, JSONB механики, отдельные переводные строки и их статусы/версии, book toggle, Goose миграция.
- REST API Chi v1: read-only lookup/search/filter/sort/pagination/export, языковой fallback, OpenAPI 3.1 и генерационная конфигурация oapi-codegen.
- pgx + pgxpool, SQLC config + SQL query contracts; `slog`, readiness/liveness, graceful shutdown.
- Go CLI: JSON/JSON Schema validation, транзакционный upsert, filtered JSON export, stats, Open5e pagination/snapshot, OpenAI-compatible локальный/облачный переводчик с glossary, enable/disable книги.
- SRD 5.2.1 data 322 монстра + 14 состояний с CC BY атрибуцией; 14 машинных RU-переводов состояний и первые 50 RU-названий монстров.
- Docker Compose, Windows BAT run/stop/restart/import, CI и Testcontainers integration test.

## Оставшиеся задачи / ограничения

- Нет наполнения SRD 5.1 (2014); endpoint адаптер готов, но источник/slug, схема категории и лицензия должны быть проверены и импортированы отдельно.
- Нет контента классов, подклассов, видов/рас, предысторий, черт, заклинаний, способностей, снаряжения, правил/level progression и большинства монстров для редакции 2024. Фактический первичный набор содержит только монстров/состояния.
- Нет сторонних издательств/Homebrew dataset; поддерживается общий JSON import, но не закончены издательские схемы, профили совместимости и проверка прав.
- Для 322 монстров нет перевода игровых блоков/механик; у первых 50 локализованы только имена. LLM-инструмент маркирует переводы как `machine`, но не запускается автоматически и не заменяет редактора. Нет встроенного аудита терминологии/метрик актуальности в API.
- Категорийная механическая нормализация сейчас сильнее для SRD monster stat blocks и conditions; Open5e ETL сохраняет прочие объекты в raw mechanics до добавления специализированных адаптеров/схем.
- SQLC и oapi-codegen configs/contracts созданы; generated SQLC Go store ещё не подключён к API, а generated OpenAPI серверные интерфейсы не являются фактическим routing layer. Маршрутизация реализована явно на Chi. Для полноценного codegen enforcement нужна следующая итерация.
- Нет API-auth/admin endpoints, rate limiting, метрик/трейсинга, multi-tenant пользовательских наборов, разрешений на редактирование/публикацию, продакшен секретов и VPS TLS/proxy конфигурации.
- Дедупликация идёт по стабильному source/external ID плюс точному ID снимка; fuzzy/семантические cross-source merges намеренно не выполняются. JSON Schema задаёт форму `relations`/`requirements`/`choices`, но проверка существования целевых ID/циклов связей не реализована; текущий SRD-снимок таких ссылок не содержит.
- В этой среде отсутствует установленный Go toolchain/Docker, поэтому тесты, `go vet`, генерация кода, Testcontainers и сборку контейнера локально выполнить не удалось. `go.sum` также не сформирован локально; CI сначала выполняет `go mod tidy`, затем компиляцию, но lock-файл следует получить/закоммитить после запуска с Go 1.27.4. CI workflow настроен на проверки в GitHub Actions; до merge статус CI надо проверить.
