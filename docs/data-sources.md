# Источники данных и политика наполнения

Дата ревизии источников в этом снимке: 2026-11-26.

## Подключённый открытый набор

- **D&D System Reference Document 5.2.1 (2024)** — материал Wizards of the Coast, распространяемый по CC BY 4.0. В репозитории сейчас сохранены структурированные JSON-данные `322` монстров и `14` состояний. Основа JSON: [adkinn/srd-5.2.1](https://github.com/adkinn/srd-5.2.1), который указывает источник данных Open5e API и SRD 5.2.1; исходный блок атрибуции встраивается в каждую сущность. Детальная лицензия/атрибуция находится в `data/catalog/2024/LICENSE`.
- [Официальная страница SRD 5.2.1](https://www.dndbeyond.com/sources/dnd/srd-5.2.1) и [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) — нормативные ссылки для атрибуции.

## Подготовленные интеграции

- **Open5e API v2**: `rules sync-open5e` получает постраничный JSON и нормализует его в стабильный внутренний формат. Можно подключать отдельные открытые документы и редакции. Параметры `--license` и `--attribution` обязательны; инициатор синхронизации обязан сверить документ и права. Не вся информация из произвольной записи Open5e превращается в нормализованные игровые характеристики: оригинальный объект сохраняется в `mechanics` для дальнейшего категорийного адаптера.
- **5e-bits/5e-database** ([GitHub](https://github.com/5e-bits/5e-database)): структура категорий/редакций изучена как кандидат на будущий локальный ETL. Данные оттуда не включены автоматически в публичный каталог: кодовая лицензия репозитория не должна трактоваться как лицензия каждого текстового поля/источника. Сначала проверяются происхождение и права на конкретный document.
- Другие издательства, Homebrew и собственные источники: через canonical JSON import. Для каждого набора добавьте лицензию, источник, редакцию, издателя, книгу, версию, атрибуцию и подтверждённые права.

## Не публикуется

Тексты официальных книг вне SRD, платные дополнения, приключения и сторонние материалы не извлекаются/не перепубликуются без разрешения. Поддержка дополнительных книг — это возможность включить лицензированный или частный отдельный каталог, не утверждение, что такие данные уже собраны. Записи, для которых разрешена только ссылка/фактический индекс, нужно хранить отдельно с минимальным разрешённым набором и явными условиями источника.

## Обновление

1. Проверить действующий API endpoint, document slug, version и лицензию.
2. Создать новый снимок через `rules sync-open5e`; не обновлять production DB напрямую.
3. Проверить список/количество, стабильность ID, дубли, обязательные metadata и JSON Schema.
4. Review diff исходных JSON, атрибуции, механических изменений и перевода.
5. Обновить Git-источник, импортировать в PostgreSQL и сверить API / агрегаты.

Запросы к API во время работы никогда не скачивают обновления сами.
