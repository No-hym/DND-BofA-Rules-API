# Развёртывание

## Docker Compose

См. быстрый старт в корневом README. Compose запускает PostgreSQL 17 с named volume, API и отдельную seed-команду профиля `tools`. API-контейнер применяет Goose миграции перед стартом. Импорт данных — отдельная команда; API не загружает контент автоматически при каждом рестарте.

## Linux VPS

1. Настроить `POSTGRES_PASSWORD`/`DATABASE_URL` через secret manager/переменные окружения; не коммитить `.env`.
2. Использовать TLS до PostgreSQL и ограничить сеть: наружу выставлять только API за reverse proxy с TLS/лимитами запросов. Для публичного API добавить rate limiting, метрики и auth для административных инструментов.
3. Выполнить миграции `goose -dir db/migrations postgres "$DATABASE_URL" up`, импортировать лицензированный каталог через `rules import`, запустить `rules-api` с `HTTP_ADDR=:8080`.
4. Резервировать PostgreSQL и Git-исходники независимо; отработать восстановление из миграций + повторного импорта.
5. Настроить readiness на `/readyz`, liveness на `/healthz`, ограничение CPU/RAM, логирование stdout в JSON и план обновления/рецензирования контента.

Откат схемы/данных — согласованная операция; Goose `Down` не следует запускать автоматически. API пока read-only для клиентов, администрирование книги доступно через доверенную CLI-команду.
